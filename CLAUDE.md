# Tenaball: notes for Claude Code

Tenable-style football quiz. Everything lives in `index.html` (HTML, CSS and JavaScript in one file, assets embedded as data URIs). `tenable-animation.html` is a standalone preview of the end-of-game trophy sequence and should stay in step with the game's version.

## Question rules (set by Craig, keep these)

- Every question has exactly 10 answers.
- No single answer may fill 4 or more slots on a board. Move the question to years that avoid it, otherwise drop it.
- Player and goals data counts only from the start of the Premier League, 1992/93. Champions League data from 1992/93, when it became the Champions League.
- World Cup and Euros team questions (winners, hosts and so on) can cover every tournament since each competition began.
- Every question states the period it covers, shown as a date line under the question.
- Figures stop at the end of the last completed season (2025/26 for now), never part-way through a season. Transfer fees may run to the end of the latest window.
- Every board shows positions 1 to 10 down the left, including year-based boards.
- Only use data that has been checked against a source. If data can't be verified, stop rather than guess.

## Writing style

- Never use em dashes in any text in the game or in docs.

## Structure pointers

- Question data: `PL`, `T5`, `UCL_W`, `UCL_R`, `EXTRA_Q`, `EXTRA_Q2`, `EXTRA_Q3`, `EXTRA_Q4` and the helper builders near them. `EXTRA_Q4` is the October 2026 Premier League records boards (managers, scoring records, transfer fees in and out), built into index.html by `scripts/build-pl-records.py`, which holds every row; edit the rows there and run it from Craig's workbook in `docs/data/`; sources and corrections are in `docs/PL_RECORDS_SOURCES.md`. A tie at a board's cut-off uses a pool (`pool` and `alts` on the slots), so any of the tied names fills the shared places. A final pass re-cuts or removes boards that break the 4-slot rule.
- Every Premier League player, 1992/93 to 2025/26 (5,082 names, Craig's dataset in `docs/data/pl_players/`, see its README for sources and checks) is embedded as `PL_PLAYERS` by `scripts/build-pl-players.py` (re-run it after updating the data). Each becomes a recognised name (`PLP`, `PEOPLE`); the game's own spelling wins where it differs (`CANON` in the script: Son, Zagorakis, Kanu, Juninho, Salva). Letter boards (`pl-letter-a` and so on, `LETTER_BOARDS`) are open boards (`q.open`): any player whose surname begins with the letter counts (both the surname's first letter and the last word's, so De Bruyne counts for B and D), answers fill from 10th up, there's no stat, and at the end empty places show well-known examples (most appearances, `openExamples`). Rare letters share a board (I, Q or U; X, Y or Z). Boards with 200 or more players are easy, the rest medium.
- Drawn boards: club record scorers (`CLUB_REC`) aren't a fixed ten. `pickQuestion` swaps each level's board (`pl-club-rec-0` to `-2`) for a fresh draw (`drawClubRec`), and the clubs chosen travel in the board's id, for example `pl-club-rec-1:0.4.12...`. Look boards up with `findQ(id)`, not `Q.find`, so every phone in an online game rebuilds the same draw.
- Difficulty: `q.level` (0 easy, 1 medium, 2 hard); the home screen slider picks the level. The All levels switch (`cfg.allLevels`, on by default; phones that saved their setup before it became the default, with no `v: 2` in `tenaball-setup`, get it switched on once) greys the slider out and `pickQuestion` picks a level at random for each board, so each level gets a fair share. Online rooms send All levels as level 3.
- Competitions: the home screen's box opens a slide-up panel of toggles (`#compSheet`, grouped by `COMP_GROUPS`, with quick picks). The ticked list is `cfg.cats`; `nextCat` picks one per round, never the same twice running. Ticks and All levels are saved on the phone (`tenaball-setup`), and the host's travel to every phone in an online game as `settings.cats`. Flags and badges are drawn SVG (`compIcon`), not emoji, which don't show on Windows or show England and Scotland on many Android phones. A competition in `COMP_GROUPS` but not in `ALL_CATS` (the Europa League for now) shows greyed out as "Coming later".
- Home screen layout: the settings sit in three panels (`.homegrp`): Who's playing (players, names), The game (rounds, competitions, difficulty) and House rules (shot clock, repeated answers). The home screen is sized close to the game screens: the logo is 250px wide on a 390px phone (64vw, against 46vw in a game) and labels, pills and boxes are a touch smaller than the defaults (the block under "home screen: a little smaller" in the CSS). Its watermark is the ball from the Tenaball logo (`#setup .wmk`, `assets/watermarks/home.png`), at the top right below the logo and fainter than the competition marks (5 percent).
- Home screen help: each section heading has a small i (`.finfo`, `data-info`) that opens `#infoSheet`, a slide-up panel like the competitions one, with text from `INFO`. How to play at the bottom opens the same panel with the rules (kept in the `#howText` template). Rounds can be 1, 3, 5 or 7.
- Club badges: `badge(name)` draws a crest from the badge pack when the club has one, otherwise the old two-colour circle. Crests are transparent 72px PNGs embedded as base64 in their own `<script>` (`BADGE_IMG`), found by the game's own club name through `BADGE_FILE` (`crestKey`, which ignores case and accents and follows aliases). A pack row with two names (`RB Salzburg|Red Bull Salzburg`) answers to both. Arles, Lleida, Merida and Salamanca have no badge and keep the circle. Crests are 32px on the board and 26px in suggestions, each in a fixed cell (`.bcell`) so crests, circles and flags line up, and centred with the text in suggestion pills. Every embedded crest is re-made from the 128px masters by `scripts/size-badges.py` so they all look the same size: each is scaled so the square root of its width times height is the same (round crests about 25px across on the board), capped so its long side fits, and centred; `TRIM` in the script shrinks a couple of heavy wide crests. Run it again after adding a badge. No backing or white circle behind any crest (Craig dropped it), so very dark crests such as Spurs, Juventus and Derby are hard to see on dark rows; that is accepted. A missed row fades its name to 65 percent but not its crest (the name is wrapped in `.nm`). Crests and UEFA logos are trademarks: fine for this private family game, not for a public release. To add or rename a badge, update `assets/badges/clubs.csv` (its `game_name` must match the game's name) and regenerate `BADGE_FILE` and `BADGE_IMG`, then run `scripts/size-badges.py`.
- Flags and competition icons: country boards use circle flags from the pack (`NATION_FLAG`, `FLAG_IMG`, `badgeN`), 24px on the board and 19px in suggestions; Czechoslovakia, the Soviet Union and Yugoslavia have no flag in the pack, so `FORMER_FLAG` draws simple circle flags for them. The home screen's competition box and panel (`compIcon`) use the same circle flags, a circle of five stripes for Top 5 Leagues, the pack's Champions League starball and Europa League trophy (`LOGO_IMG`), and a drawn World Cup trophy on a round base. Year-labelled boards (`.tower.shortlab`) get a narrow label column so names fit, and names on those boards stay on one line with an ellipsis.
- Badge library: every badge we have (1,538 crests at 72px and 128px masters, every flag, the competition logos, and the CSV and JSON name tables) is stored in `assets/badges/` (see its README). The game embeds only what it uses. Brief for competition background artwork: `docs/BACKGROUND_ARTWORK_BRIEF.md`.
- Variety: `family(q)` groups questions by type; `pickQuestion` favours the least recently played type.
- Themes: `body[data-cat=...]` CSS blocks per competition. Each competition also has a faint watermark at the top right of the game screen (`WATERMARK`, set by `theme()`, drawn in `#game .wmk`, fading in from behind the sound and exit buttons so it shows from just below them, with a radial fade to nothing on every side; white marks at 13 percent, coloured ones at 20, or the entry's own `op`). Picks: Premier League lion, LaLiga logo, Bundesliga player, Italy scudetto, Ligue 1 logo, SPFL lion, the five league countries' flags in a ring around a football for Top 5 (drawn by `scripts/top5-watermark.py`), Champions League starball, World Cup trophy, Henri Delaunay trophy for the Euros, and the Europa League trophy ready for when that competition and its orange theme arrive. Originals and sources are in `assets/watermarks/` (`candidates.json`). A new competition needs its own entry. Found rows look the same in every theme (no coloured bar across the top on the Champions League board).
- Premier League season tables (`pl-top`, `pl-mid`, `pl-bot`) show each club's final points (`PL_PTS`, same order as `PL`, after deductions). Sources and checks are in `docs/PL_POINTS_SOURCES.md`. Add the new season's points when adding a season to `PL`, or the page stops with an error.
- Phone status bar: iOS Safari paints it one solid colour taken from a fixed full-width strip at the top (`.topfade`, and each overlay's own `::before`); Android Chrome uses `<meta name="theme-color">`, which `syncChrome()` keeps on the colour at the top of the screen. Safari ignores a strip 10px or thinner, one below the page (negative z-index), or a see-through one that ignores taps, so the strips are 16px, z-index 0, and the page (`.toplogo`, `.wrap`) sits above them at z-index 1. Each theme sets `--topc` (its average top-edge colour) and each full-screen overlay sets `--band`. A new theme or overlay needs one of these, or a band shows under the status bar.
- Sound: the game's own sounds are synthesised (`sfx`, `tone`, `bell`, `whistle`). Craig's recorded crowd takes (`assets/sounds/crowd/`, embedded as `CROWD_MP3` by `scripts/embed-crowd.py`) play under them, never instead of them, through `crowdPlay(kind)`: a cheer for a right answer (a big cheer for several slots or slot 10), a groan for a wrong answer or time up, boos with every yellow (softer) and red card, a roar for a full board, applause at full time (a groan for a solo game on 0). Each kind's volume (`CROWD_VOL`) is set from its measured level so the crowd sits under the chimes; a new crowd sound fades out the last, and mute stops it. Whistles: one short blast for every card and for time up; the three-blast whistle (`sfx.fullTime`) is only for the end of the game.
- Stats: win rate and win streaks count only games against other players (`multi`). Solo games count towards games, best score, average and full boards, and the stats panel says so.
- End of game: `endGame()` builds the final table, records stats (`recordGame`), then runs `trophyReveal()` which hands the winner pill into first place. The trophy sequence is a signed-off copy of `tenable-animation.html`: keep its artwork, timings, colours and effects identical to the preview. `closeTrophy()` stops everything in the overlay (animations, the ribbons' SVG ripple, the idle bolt timer, leftover confetti) whenever it closes; `tests/trophy.test.mjs` checks the sequence and the hand-over. A solo game that ends on 0 points has no winner: no trophy and `-` instead of a place in the table and the share message (`tests/game.test.mjs`). Every game ends with a banter line under the table and in the share message (`banterLine`, `banterKind`, lines in `BANTER`; Craig wants it sarcastic, rude and crude). The rules work on shares of the game's slots (rounds x 10): solo goes by the player's share (0, poor, mid, good, great, perfect); multiplayer takes the first rule that fits: everyone on 0, a tie for first, a table that found hardly anything, a chasm between first and last, a runaway winner, last place on 0, a close finish, then the winner's own score. The pick is seeded from the result, so every phone in an online game shows the same line, and each phone skips lines it showed recently (`tenaball-banter`). Add lines to any list freely; placeholders are listed above `BANTER`.
- Accounts and online games: the last `<script>` in `index.html` talks to the server in `server/` (a Cloudflare Worker). `TENABALL_SERVER` switches them on (null means offline, as before). Accounts are an email plus a 4-digit PIN; there's no email checking or PIN recovery by email, Craig resets PINs from the server's `/admin` page. Stats: `recordGame` keeps local stats for everyone except the signed-in player, whose results go to their account through `accountRecord`.
- Online play is a replayed move log. The server's room puts moves in one order, checks the sender is in the game, and lets only the host send `round`, `reveal`, `refresh`, `next` and `skip`; players send `guess`, `pass` and `timeout`. Every phone applies them in order through `applyAction`, which calls the same `applyGuess`, `applyPass`, `applyTimeout`, `applyReveal`, `applyRefresh` and `applyNext` a local game uses. Keep those deterministic: no randomness, clock reads or local-only state in them, or phones will drift apart. Question picking happens only on the host, and the chosen id travels in the move.
- Tests: `cd tests && npm install && (cd ../server && npm install) && npm test` runs the server tests, the account and multi-phone online tests (against a local copy of the server) and the trophy tests. Run them after changing the server, the online code, the game loop or the end of game.
- Sharing: `prepareShare()` runs from `endGame()`. It builds the WhatsApp-style message (`shareText`, where `*text*` is bold) and draws the results card image (`shareCard`, 1080 by 1350) ahead of time, so tapping Share opens the share sheet straight away. `og-image.jpg` plus the `og:` meta tags give the link preview; it is the one asset kept outside `index.html`, because link previews need a real image URL.
